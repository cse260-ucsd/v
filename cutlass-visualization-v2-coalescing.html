Coalesced loads

The GPU runs threads in groups called warps and sends each warp's loads to memory together. If the threads in a warp read neighboring addresses, memory can hand them all over in one piece. Which index the kernel takes from threadIdx.x decides whether that happens.

Part 1's kernel took row from threadIdx.x. That's the first layout below. Swapping two lines so that col comes from threadIdx.x makes the loads coalesced.

What changed

Both layouts do the same arithmetic on the same numbers. The only difference is the two index lines: which of row and col comes from threadIdx.x. Threads with neighboring threadIdx.x share a warp, so that choice decides whether a warp reads neighbors in memory. When it does, the GPU combines the warp's loads into one request. That's a coalesced load.

Matrices are stored row by row, so neighbors in memory sit along a row. The rule of thumb: let threadIdx.x run along the dimension that is contiguous in memory.

Real warps have 32 threads, not 4. With the uncoalesced layout, one load from A touches 32 separate pieces of memory. With the coalesced layout, the warp reads B as one 128-byte piece.
