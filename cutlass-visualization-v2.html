CUTLASS, step by step · Part 1

The naive kernel

Each element of C is a row of A times a column of B. The simplest CUDA kernel gives every element of C its own thread and runs all of those threads at the same time.

64 threads, all running at once

Hover a thread in C to see its block and what it reads. Hover a value in A or B to see who loads it.

Launch · runs on the CPU
dim3 block(2, 2); // blockDim: 2 × 2 threads dim3 grid(N / 2, N / 2); // gridDim: 4 × 4 blocks matmul<<<grid, block>>>(A, B, C, N);
Kernel · every thread runs this
__global__ void matmul(const float *A, const float *B, float *C, int N) { int row = blockIdx.x * blockDim.x + threadIdx.x; int col = blockIdx.y * blockDim.y + threadIdx.y; float acc = 0.0f; for (int k = 0; k < N; k++) acc += A[row * N + k] * B[k * N + col]; C[row * N + col] = acc; }

All 64 threads are on the highlighted line at the same moment. They differ only in row and col.

Why it's slow

Hover any value in A: all 8 threads in that row load it, each one separately. Every number in A and B gets fetched 8 times, so the threads make 1,024 loads to read just 128 numbers.

On a GPU, reading memory is much slower than doing arithmetic, so these threads spend most of their time waiting for data. A later part fixes that with tiling: a block of threads loads its piece of A and B once into fast on-chip memory and shares it. First, Part 2 looks at how each warp of threads reads memory.
