Cache blocking

In Part 2's kernel, the 16 threads of a block need the same few rows of A and columns of B, yet each thread fetches its own copy from global memory. Cache blocking has the block fetch each number once into shared memory, then lets every thread read it from there.

Shared memory is small, so the block works through A and B one tile at a time.

Kernel · pseudo-code
kernel matmul_tiled(A, B, C, N): shared As[4][4], Bs[4][4] tx, ty = threadIdx.x, threadIdx.y row = blockIdx.y · 4 + ty col = blockIdx.x · 4 + tx acc = 0 for t in 0 .. N/4 − 1: As[ty][tx] = A[row][4t + tx] Bs[ty][tx] = B[4t + ty][col] sync() for k in 0 .. 3: acc += As[ty][k] · Bs[k][tx] sync() C[row][col] = acc

What changed

Part 2's kernel asked global memory for every number it used: 1,024 reads in all. Now each number comes from global memory once per block and is then read by 4 threads from shared memory: 256 reads, 4 times fewer.

The saving equals the tile width. Real kernels use tiles of 32 × 32 or more, so they save more. The price is two sync() barriers per tile.
